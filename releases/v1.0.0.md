Fabrica Public Rules Library v1.0.0 is the first release. It contains 119 rules in 12 groups that tell coding agents how to write testable, maintainable, production-grade code. Import them into any project with [Code Rules](https://github.com/fabricahq/code-rules).

## ✨ New Features

### Every rule follows the Code Rules rubric

Each rule states one obligation and says when an agent should read it. It then gives implementation guidance, incorrect and correct examples, and the evidence a reviewer should look for. Examples were checked against current library sources and compiled where possible. See the [rule rubric and template](https://code-rules.fabricahq.com/reference/rule-authoring/), or read [Reproduce bugs with regression tests](https://github.com/fabricahq/public-rules/blob/v1.0.0/practices/testing/test-bug-fixes-before-fixing.md) for a representative rule.

The Testing group also ships Fabrica's [testing philosophy](https://github.com/fabricahq/public-rules/blob/v1.0.0/assets/testing-philosophy.md) as background reading. Every testing rule still stands on its own, so you can import or exclude them individually.

### Import all of the library or only what you need

With [Code Rules installed](https://code-rules.fabricahq.com/start-here/install/) and your [project set up](https://code-rules.fabricahq.com/start-here/set-up-project/), add the library and sync:

```sh
code-rules project add library fabrica \
  --repository https://github.com/fabricahq/public-rules.git \
  --groups '*' \
  --ref v1.0.0
code-rules project sync
```

Use `--groups 'practices/*'` or `--groups 'techs/*'` for one kind of group, or repeat `--groups` with individual group IDs such as `techs/react`. To leave out individual rules, see [Exclude a rule](https://code-rules.fabricahq.com/guides/select-rules/#exclude-a-rule).
